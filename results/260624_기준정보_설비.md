## 1. 개요
설비정보(Equipment)는 공장 내에서 가공 및 생산에 직접 사용되는 기계 장치와 설비의 기준 마스터 정보입니다. 기존 레거시의 복잡하고 비필수적인 필드(시간당 사용료, 차지면적, 검교정일 등 20여 개)를 과감하게 배제하고, 현업의 요구사항인 8대 핵심 필드 위주로 스키마를 다이어트하여 단순화합니다. 특히 설비의 총 사용 횟수(누계 샷)와 최대 가동 한계(설계 샷)를 분석하여 최적의 설비 교체 시기를 파악할 수 있는 비즈니스 메커니즘을 제공합니다.

## 2. 데이터베이스 설계안 (EI_MT / REI_MT)
설비 정보 및 이력 정보 테이블은 8대 핵심 필드를 기반으로 하며, 외래키 식별 대원칙에 따라 정수형 기본키(`Index`) 매핑을 적용합니다.

### 2.1. 설비 정보 테이블 (EI_MT)
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `EquipmentNum` | `VARCHAR(100)` | NOT NULL | 설비번호 (내용키, 식별자 코드) |
| `EquipmentName` | `VARCHAR(255)` | NOT NULL | 설비명 |
| `EquipmentCategoryIndex` | `INT` | NOT NULL | 설비분류 식별 인덱스 (FK, 공용코드 PUC_MT 참조) |
| `WCIndex` | `INT` | NULL | 사용 작업장 식별 인덱스 (FK, WCI_MT 참조, 미매핑 시 NULL 허용) |
| `DesignShot` | `INT` | NOT NULL | 설계 샷 (설비 고유의 최대 사용 한계 연한 횟수) |
| `InitialShot` | `INT` | NOT NULL | 초기 샷 (회사 도입 시점의 기사용 횟수, 기본값 0) |
| `AccumulatedShot` | `INT` | NOT NULL | 누계 샷 (초기 샷 + 작업 샷, 성능을 위한 컬럼 관리) |
| `WorkShot` | `INT` | NOT NULL | 작업 샷 (실제 작업 시 가동된 누적 횟수, 기본값 0) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (소프트 삭제용 플래그, 기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 등록자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 등록일시 |
| `UpdatingPerson` | `VARCHAR(255)` | NULL | 수정자 |
| `UpdatingDate` | `DATETIME` | NULL | 수정일시 |

### 2.2. 설비 이력 정보 테이블 (REI_MT)
설비 마스터 데이터의 변경 및 이력을 관리하기 위한 테이블입니다.
- 2.2.1. 구조 및 명세는 마스터 테이블(`EI_MT`)과 동일합니다.
- 2.2.2. 인덱스 설정은 조인 최적화를 위해 동일하게 유지합니다.

> [!important] 외래키(FK) 맵핑 대원칙 적용
> - `EquipmentCategoryIndex`는 공용코드 테이블(`PUC_MT`)의 대분류가 '설비분류'인 소분류 레코드의 `Index`를 가리킵니다.
> - `WCIndex`는 작업장 마스터 테이블(`WCI_MT`)의 `Index`를 가리킵니다.

## 3. 핵심 비즈니스 로직 및 제약 사항

### 3.1. 설비 교체 시기 도래 분석 로직
- 3.1.1. **누계 샷 자동 연산 규칙:** 누계 샷(`AccumulatedShot`)은 시스템 상에서 **'초기 샷(InitialShot) + 작업 샷(WorkShot)'**으로 자동 연산되어 관리됩니다.
- 3.1.2. **설비 교체 임계치 판정:** 누계 샷이 설계 샷(`DesignShot`)에 도달하거나 이를 초과하는 시점(`AccumulatedShot >= DesignShot`)이 되면 설비 사용 수명이 다한 것으로 판정하여 시스템 화면 상에 **'설비 교체 필요' 경고 알림**을 시각적으로 표출합니다.

> [!warning] 용어 정의 교정 안내
> 사용자 피드백 중 *"누계샷이 설비초기샷과 값이 동일하면 연한이 다된 것"*이라는 언급은 비즈니스 흐름상 **"누계 샷이 설계 샷(최대 한계 연한)과 동일하면 연한이 다된 것"**의 오타로 판단하여 이를 정정해 설계에 반영하였습니다. 초기 샷은 도입 당시 고정값이며, 가동이 누적됨에 따라 누계 샷이 최종 도달해야 하는 임계치는 설계 샷(사용연한)이기 때문입니다.

### 3.2. 내용키 유일성 및 정합성 검증
- 3.2.1. **설비번호 중복 검증:** 활성 데이터(`RecodingState = 1`) 상태 내에서 설비번호(`EquipmentNum`)는 고유해야 합니다.
- 3.2.2. **샷(Shot) 값 정수 제약:** 설계 샷, 초기 샷, 작업 샷은 모두 음수일 수 없으며 0 이상의 정수 형태여야 합니다.

## 4. 화면 (UI/UX) 구성안 (다이어트 2분할 레이아웃)
기존 레거시 화면의 20여 개 입력 요소를 덜어내고, 사용자가 요청한 8대 핵심 데이터 위주로 심플하게 구성합니다.

### 4.1. 좌측 영역 (설비 목록 그리드)
- 4.1.1. 상단에 설비분류 필터와 설비명/설비번호 통합 검색 바를 배치합니다.
- 4.1.2. 그리드 컬럼은 `설비번호`, `설비명`, `설비분류`, `사용 작업장`, `설비 수명 진행률(ProgressBar UI)`로 구성합니다.
  - **수명 진행률 UI:** `(누계 샷 / 설계 샷) * 100`으로 계산된 값을 시각적인 게이지 바(ProgressBar)로 표현하여 교체 임박 설비를 한눈에 식별할 수 있도록 돕습니다. (예: 90% 이상 도달 시 적색 게이지 표시)

### 4.2. 우측 영역 (상세 정보 폼)
- 4.2.1. 필수 등록 항목인 `설비번호`, `설비명`, `설비분류`, `설계 샷`, `초기 샷`을 입력할 수 있도록 폼을 구성합니다.
- 4.2.2. **자동 연산 필드 시각화:** `작업 샷`과 `누계 샷` 필드는 읽기 전용(Read-only) 회색 음영으로 처리하여 사용자가 직접 수정할 수 없고 시스템에서만 자동 누적 연산되도록 인지시킵니다.
- 4.2.3. **작업장 연결 드롭다운:** 공장에서 운영 중인 작업장 목록(`WCI_MT` 기반)을 콤보박스로 조회 및 매핑할 수 있도록 선택지를 제공합니다.
