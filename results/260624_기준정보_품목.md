## 1. 개요
품목정보는 ERP 시스템에서 다루는 모든 자재, 원료, 반제품, 완제품, 상품 등을 총괄하는 핵심 마스터 데이터입니다. 기존 레거시의 무수히 산재된 불필요한 속성 필드들을 11대 필수 필드 중심으로 압축 다이어트하고, 복잡하고 파편화되어 있던 창고 배정 및 재고 레코드 동적 생성 로직을 현대적인 창고 마스터 및 통합 재고(Inventory) 관리 아키텍처로 개편합니다.

## 2. 데이터베이스 설계안 (창고 및 재고 연동 구조)

### 2.1. 품목 마스터 테이블 (II_MT)
다이어트된 품목의 핵심 데이터와 기본 창고 매핑 정보를 담습니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `ItemNum` | `VARCHAR(255)` | NOT NULL | 품목 번호 (대체 키) |
| `ItemName` | `VARCHAR(255)` | NOT NULL | 품목 명칭 |
| `AssetClass` | `VARCHAR(100)` | NOT NULL | 자산 분류 (제품, 상품, 원자재, 반제품) |
| `Unit` | `VARCHAR(50)` | NOT NULL | 기본 관리 단위 |
| `Standard` | `VARCHAR(255)` | NULL | 규격 |
| `CheckDistinction` | `VARCHAR(100)` | NOT NULL | 검사 구분 (무검사, 샘플검사, 전수검사) |
| `LeadTime` | `INT` | NOT NULL | 조달 리드타임 (일 단위) |
| `SafetyStockQuantity` | `DECIMAL(19,4)` | NOT NULL | 안전 재고량 (기본값 0) |
| `OrderIntervalQuantity` | `DECIMAL(19,4)` | NOT NULL | 발주 간격 수량 (기본값 0) |
| `MinOrderQuantity` | `DECIMAL(19,4)` | NOT NULL | 최소 발주량 (기본값 0) |
| `StandardUnitCost` | `DECIMAL(19,4)` | NOT NULL | 기준 단가 (기본값 0) |
| `DefaultWarehouseIndex` | `INT` | NOT NULL | 기본 보관 창고 일련번호 (FK, Warehouse_MT 참조) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (소프트 삭제용 플래그, 기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 등록자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 등록일시 |
| `UpdatingPerson` | `VARCHAR(255)` | NULL | 수정자 |
| `UpdatingDate` | `DATETIME` | NULL | 수정일시 |

### 2.2. 창고 마스터 테이블 (Warehouse_MT)
물리적/논리적 보관 장소를 정의하는 마스터 테이블입니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `WarehouseCode` | `VARCHAR(50)` | NOT NULL | 창고 코드 (예: WH01, WH02...) |
| `WarehouseName` | `VARCHAR(100)` | NOT NULL | 창고 명칭 (영업창고, 원자재창고, 생산창고, 외주창고 등) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (기본값 1) |

### 2.3. 창고별 품목 재고 테이블 (Inventory_T)
각 창고별 실시간 품목 재고 수량을 기록하는 실시간 트랜잭션 테이블입니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `ItemNum` | `VARCHAR(255)` | NOT NULL | 대상 품목 번호 (FK) |
| `WarehouseIndex` | `INT` | NOT NULL | 대상 창고 일련번호 (FK) |
| `RealStockQuantity` | `DECIMAL(19,4)` | NOT NULL | 현재 실재고 수량 (기본값 0) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (소프트 삭제용 플래그, 기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 등록자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 등록일시 |
| `UpdatingPerson` | `VARCHAR(255)` | NULL | 수정자 |
| `UpdatingDate` | `DATETIME` | NULL | 수정일시 |

## 3. 비즈니스 로직 및 통합 프로세스 개편안

### 3.1. 기존 창고 레코드 자동 분산 생성의 문제점 극복
- 3.1.1. **레거시 문제점:** 품목 등록(제품/상품/원자재 -> 영업/원자재창고), 공정 등록(반제품 -> 생산창고), 외주 등록(외주창고) 등 각 시점마다 하드코딩된 동적 쿼리가 데이터베이스 이곳저곳에 흩어져서 임의로 재고 행을 끼워 넣어 데이터 정합성 관리가 불가능했습니다.
- 3.1.2. **개편 해결책 (통합 서비스 패턴):** 품목 등록 시점에 화면에서 **'기본 보관 창고'**를 필수로 지정받습니다. 품목 등록 트랜잭션이 완료되는 시점에 백엔드의 `ItemService` 내부에서 기본 보관 창고에 매핑되는 초기 재고 행(RealStockQuantity = 0)을 `Inventory_T` 테이블에 **자동으로 1회만 단일 생성**합니다.
- 3.1.3. 이후 공정 등록이나 외주단가 등록 시점에는 데이터베이스에 임의의 재고 행을 끼워 넣는 행위를 전면 금지하며, 실제 입고/출고/이동 등의 물류 트랜잭션이 발생할 때만 `Inventory_T` 테이블의 재고 수량 가감 연산(UPDATE)을 수행하도록 로직을 일원화합니다.

> [!important] 화면(UI/UX) 구현 편의성 제안
> 품목 등록 화면에서 사용자가 '자산분류'를 선택할 때, 시스템이 기본 창고를 자동으로 추천 세팅해 주어 수작업 입력을 돕습니다.
> - 원자재 선택 시 -> **'원자재 창고'** 자동 추천 매핑
> - 제품 / 상품 선택 시 -> **'영업 창고'** 자동 추천 매핑
> - 반제품 선택 시 -> **'생산 창고'** 자동 추천 매핑
