## 1. 개요
거래처정보는 ERP 시스템에서 매출(수주)과 매입(구매/외주/비용) 업무가 발생하는 모든 거래 대상을 관리하는 기준 마스터 정보입니다. 기존의 복잡하고 비정규화된 구조를 탈피하여 필수 필드 중심으로 다이어트하고, 거래처 구분을 유연하게 다중 매핑할 수 있는 3차 정규형 구조로 리팩토링합니다.

## 2. 데이터베이스 설계안 (3개 테이블 분리)

### 2.1. 거래처 마스터 테이블 (CI_MT)
필수 입력 및 추적 정보만으로 경량화한 마스터 테이블입니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `BusinessRegistrationNum` | `VARCHAR(255)` | NOT NULL | 사업자등록번호 (대체 키) |
| `CompanyName` | `VARCHAR(255)` | NOT NULL | 거래처 명칭 |
| `PresidentName` | `VARCHAR(255)` | NOT NULL | 대표자명 |
| `Address` | `VARCHAR(255)` | NOT NULL | 사업장 기본 주소 |
| `ContactPerson` | `VARCHAR(255)` | NOT NULL | 거래처 담당자명 |
| `Phone` | `VARCHAR(255)` | NOT NULL | 연락처 (전화번호) |
| `Email` | `VARCHAR(255)` | NOT NULL | 담당자 이메일 주소 |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (소프트 삭제용 플래그, 기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 등록자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 등록일시 |
| `UpdatingPerson` | `VARCHAR(255)` | NULL | 수정자 |
| `UpdatingDate` | `DATETIME` | NULL | 수정일시 |

### 2.2. 거래처 구분 마스터 테이블 (CompanyType_MT)
거래처의 역할 유형 데이터를 고정 관리하는 마스터 테이블입니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `TypeCode` | `VARCHAR(50)` | NOT NULL | 구분 코드 (예: C001, C002...) |
| `TypeName` | `VARCHAR(100)` | NOT NULL | 구분명 (수주거래처, 구매거래처, 외주거래처, 비용거래처) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (기본값 1) |

> [!note] 초기 고정 데이터 구성
> - C001: 수주거래처
> - C002: 구매거래처
> - C003: 외주거래처
> - C004: 비용거래처

### 2.3. 거래처 구분 매핑 테이블 (CompanyTypeMapping_T)
거래처와 거래처 구분을 다중 연관 지어주는 N:M 관계 맵핑 테이블입니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `BusinessRegistrationNum` | `VARCHAR(255)` | NOT NULL | 대상 거래처의 사업자등록번호 (FK) |
| `TypeCode` | `VARCHAR(50)` | NOT NULL | 대상 거래처 구분의 유형 코드 (FK) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 매핑 데이터의 소프트 삭제 상태 (기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 매핑 처리자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 매핑 처리일시 |

## 3. 비즈니스 로직 및 제약 사항

### 3.1. 거래처 등록 및 수정 시 유효성 검증 (Validation)
- 3.1.1. **필수 입력 검증:** 거래처명, 대표자명, 사업자등록번호, 주소, 담당자, 연락처, 이메일 누락 여부를 서버 사이드에서 검증합니다.
- 3.1.2. **중복 사업자번호 체크:** 사업자등록번호(`BusinessRegistrationNum`)는 중복 등록할 수 없습니다.
- 3.1.3. **구분 매핑 강제화:** 거래처를 등록할 때 반드시 거래처 구분(`TypeCode`)이 **최소 1개 이상** 전달되어 매핑 테이블(`CompanyTypeMapping_T`)에 함께 인서트되어야 합니다. 그렇지 않은 요청은 트랜잭션 롤백 처리를 수행합니다.

### 3.2. 매입/매출 실적 조회 및 통계 구현 방안
- 3.2.1. **수주거래처(C001) 연동:** 거래처가 수주거래처로 매핑된 경우 매출 거래 역사 테이블(`SH_HT` 또는 `RO_HT`)을 연동하여 거래처별 매출 총액을 집계합니다.
- 3.2.2. **구매/외주거래처(C002, C003) 연동:** 해당 거래처가 구매 또는 외주거래처로 매핑된 경우 매입 역사 테이블(`BDR_HT` 또는 `BO_HT` 등)을 연동하여 거래처별 매입 총액을 집계합니다.
- 3.2.3. **연월별 총 통계 쿼리 구조:**
  - **매출 통계:** `SELECT YEAR(Date) as Year, MONTH(Date) as Month, SUM(TotalCost) as Sales FROM SalesHistoryTable WHERE BusinessRegistrationNum = @comnum GROUP BY YEAR(Date), MONTH(Date)`
  - **매입 통계:** `SELECT YEAR(Date) as Year, MONTH(Date) as Month, SUM(TotalCost) as Purchases FROM PurchaseHistoryTable WHERE BusinessRegistrationNum = @comnum GROUP BY YEAR(Date), MONTH(Date)`
  - 위 두 통계 데이터를 거래처 아이디(사업자번호) 기준으로 연월별 `Outer Join`하여 한눈에 매입/매출 실적을 비교할 수 있도록 REST API를 제공합니다.

> [!tip] 다중 매핑 거래처에 대한 인사이트
> 한 거래처가 수주거래처와 구매거래처 역할을 동시에 수행할 경우, 하나의 화면에서 매출/매입 탭을 분리하여 각 실적 목록을 조회할 수 있도록 프론트엔드 컴포넌트를 설계하겠습니다.

## 4. 화면 (UI/UX) 설계안
사용자 경험(UX) 극대화와 마스터 데이터 관리 본연의 목적에 충실하기 위해 **2분할 관리 화면**과 **별도 현황분석 메뉴**를 이원화하여 적용합니다.

### 4.1. 거래처 등록/관리 화면 레이아웃
- 4.1.1. **좌측 영역 (거래처 탐색 리스트 Grid):**
  - 상단에 통합 검색 바(거래처명, 사업자번호 입력) 및 거래처 구분 필터 필터링 칩(Chip) 배치.
  - 그리드 내에 거래처 기본 정보 요약과 함께 매핑된 거래처 구분(수주, 구매 등)을 직관적인 컬러 배지(Badge) 형태로 그리드에 표시.
  - 특정 행을 클릭하면 우측 정보 영역으로 데이터가 로딩됨.
- 4.1.2. **우측 영역 (상세 정보 및 편집 폼):**
  - 상단에 신규 등록(초기화), 저장(등록/수정), 삭제 버튼을 가지런히 배치.
  - 필수 7대 필드를 2열(Grid) 레이아웃으로 모던하게 디자인하여 데이터 입력 집중도를 높임.
  - 거래처 구분 선택 영역은 투박한 체크박스 대신 마우스 호버 및 클릭 액션이 가미된 **'다중 선택 칩(Multi-select Chip)'** 컴포넌트로 구현.

### 4.2. [신설] 거래처별 매입/매출 현황관리 메뉴
등록 화면의 복잡도를 낮추고 데이터 분석 효율성을 극대화하기 위해, 실적 집계 및 통계 정보는 별도의 독립된 분석 대시보드 화면으로 이관합니다.
- 4.2.1. **연간 매입/매출 추이 차트:**
  - 선택한 거래처의 연도별/월별로 발생한 매출액과 매입액을 대비하여 보여주는 2중 축(Dual-axis) 차트 제공.
- 4.2.2. **상세 거래 현황 Grid:**
  - 매출/매입 탭을 분리하여 각 거래처별 상세 거래 이력(수주 내역, 발주 내역 등)을 테이블 형식으로 조회 및 엑셀 다운로드 지원.
