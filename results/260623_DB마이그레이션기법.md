## 1. 개요
본 가이드는 기존 MSSQL-Server 환경에서 운영되던 ERP 데이터베이스 스키마를 오픈소스 데이터베이스인 MariaDB 11.4로 전환하기 위한 스키마 추출 및 DDL[^1] 변환 기법을 설명합니다. MSSQL과 MariaDB는 아키텍처와 DDL 문법이 상이하므로 데이터 타입 매핑과 제약 조건 변환 규칙을 명확히 정의하는 것이 마이그레이션 성공의 첫걸음입니다.

## 2. MSSQL 스키마 추출 기법
데이터베이스에서 스키마 구조를 추출하기 위해 SQL Server Management Studio (SSMS)를 활용합니다.
- 2.1. SSMS 접속 및 개체 탐색기에서 대상 데이터베이스 우클릭합니다.
- 2.2. `태스크(T)` -> `스크립트 생성(E)...`을 선택하여 스크립트 생성 마법사를 실행합니다.
- 2.3. 스크립팅 옵션에서 **'데이터 무시 (스키마만)'** 옵션을 반드시 지정하여 테이블 구조 DDL만 순수하게 추출합니다.
- 2.4. 외래 키 제약 조건 및 트리거를 포함할지 여부를 설정하고 파일로 저장합니다.

## 3. MSSQL to MariaDB DDL 주요 변환 규칙
추출한 MSSQL DDL 파일을 MariaDB 11.4 규격에 맞게 변환하기 위해 아래의 매핑 테이블 규칙을 적용합니다.

### 3.1. 데이터 타입 변환 규칙
| MSSQL 데이터 타입 | MariaDB 11.4 변환 타입 | 변환 가이드 및 고려사항 |
|---|---|---|
| `INT` / `BIGINT` | `INT` / `BIGINT` | 기본 정수형은 동일하게 호환됩니다. |
| `IDENTITY(1,1)` | `AUTO_INCREMENT` | 자동 증가 컬럼 지정자로 변환하며, 기본 키(Primary Key) 설정과 병행합니다. |
| `NVARCHAR(n)` / `NVARCHAR(MAX)` | `VARCHAR(n)` / `TEXT` | MariaDB는 기본 인코딩이 `utf8mb4`이므로 유니코드 접두사(N)가 필요 없습니다. |
| `DATETIME` / `SMALLDATETIME` | `DATETIME` | 시간 정보 매핑 시 그대로 사용 가능합니다. |
| `MONEY` | `DECIMAL(19,4)` | 금액 표현을 위한 고정소수점 타입으로 매핑하여 정밀도 저하를 방지합니다. |
| `UNIQUEIDENTIFIER` | `VARCHAR(36)` | UUID 문자열 크기에 맞춰 변환합니다. |
| `IMAGE` | `LONGBLOB` | 대용량 이진 데이터를 다루기 위해 매핑합니다. |
| `TEXT` / `NTEXT` | `TEXT` / `LONGTEXT` | 대용량 문자 데이터 타입으로 매핑합니다. |

### 3.2. 문법 및 기본값 변환 규칙
- 3.2.1. 대괄호 제거: MSSQL의 식별자 감싸기 기호인 대괄호(`[ColumnName]`)를 MariaDB 백틱(`` `ColumnName` ``) 기호로 일괄 변경합니다.
- 3.2.2. 기본값 함수 변경: MSSQL의 `GETDATE()`는 MariaDB의 `NOW()` 또는 `CURRENT_TIMESTAMP`로 수정합니다. `NEWID()`는 `UUID()`로 대체합니다.
- 3.2.3. 스키마 소유자 제거: MSSQL의 `dbo.TableName` 형식에서 `dbo.` 접두사를 모두 제거합니다.

## 4. 도구를 활용한 실무 변환 팁
DBeaver와 같은 데이터베이스 통합 관리 툴을 활용하면 수작업 변환 공수를 획기적으로 낮출 수 있습니다.
- 4.1. DBeaver에서 MSSQL과 MariaDB에 동시에 커넥션을 맺습니다.
- 4.2. 이관할 테이블들을 선택한 뒤 우클릭하여 `데이터 내보내기` 기능을 실행합니다.
- 4.3. 대상(Target)을 MariaDB 커넥션으로 지정하면 DBeaver가 테이블 매핑과 임시 DDL 변환을 알아서 진행해 줍니다.
- 4.4. 이 단계에서 타입 오류가 나는 컬럼만 수동으로 조율해 주면 매우 안정적으로 이관이 가능합니다.

> [!warning] 대소문자 구분 정책 주의사항
> Windows 기반 MSSQL은 테이블명 대소문자를 구분하지 않는 경우가 많으나, Linux 기반 MariaDB는 운영체제 파일 시스템 영향으로 테이블명 대소문자를 구분합니다. 이를 해결하려면 MariaDB 설정 파일(`my.cnf`)의 `[mysqld]` 섹션에 `lower_case_table_names=1` 옵션을 반드시 추가한 후 서비스를 재시작해야 레거시 소스코드의 쿼리 에러를 방지할 수 있습니다.

> [!tip] 캐릭터셋 권장 사항
> 다국어 지원 및 최신 이모지 저장을 위해 MariaDB 데이터베이스 생성 시 기본 캐릭터셋을 `utf8mb4`로 지정하고 정렬 순서(Collation)는 `utf8mb4_unicode_ci`로 구성하는 것을 강력히 추천합니다.

[^1]: **DDL (Data Definition Language)**: 데이터베이스 스키마, 테이블, 뷰, 인덱스 등의 구조를 정의하거나 수정, 삭제하기 위해 사용하는 SQL 명령어 그룹(CREATE, ALTER, DROP 등)입니다.
