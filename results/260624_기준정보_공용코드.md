## 1. 개요
공용코드는 시스템 전반에 걸쳐 다양한 기초 데이터를 분류하고 참조하기 위한 기준 마스터 정보입니다. 대분류(그룹)와 그 하위의 소분류(상세 코드) 구조를 가지며, 1:N의 계층적 연관 관계를 바탕으로 시스템의 통일성 있는 코드 체계를 유지합니다.

## 2. 테이블 설계안 (PUC_MT)
시스템 내부용 공통 제어 필드를 포함한 공용코드 테이블 구조입니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `LargeClassificationCode` | `VARCHAR(255)` | NOT NULL | 대분류 코드 |
| `LargeClassificationName` | `VARCHAR(255)` | NOT NULL | 대분류 명칭 |
| `SmallClassificationCode` | `VARCHAR(255)` | NULL | 소분류 코드 (대분류만 등록 시 NULL) |
| `SmallClassificationName` | `VARCHAR(255)` | NULL | 소분류 명칭 (대분류만 등록 시 NULL) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (소프트 삭제용 플래그, 기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 등록자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 등록일시 |
| `UpdatingPerson` | `VARCHAR(255)` | NULL | 수정자 |
| `UpdatingDate` | `DATETIME` | NULL | 수정일시 |

## 3. 등록, 수정, 삭제 비즈니스 로직 프로세스
공용코드의 무결성을 유지하기 위한 상세 C.R.U.D 처리 메커니즘입니다.

### 3.1. 등록 (Create)
- 3.1.1. **대분류 등록:** 대분류코드와 대분류명만 입력받고, 소분류 정보는 공란으로 하여 신규 행을 저장합니다.
- 3.1.2. **소분류 등록:** 왼쪽 트리/그리드에서 특정 대분류를 선택한 상태에서 소분류코드와 소분류명을 추가합니다. 이때 선택된 대분류의 코드 및 명칭 정보와 매핑하여 새로운 소분류 행을 생성합니다.

### 3.2. 수정 (Update)
- 3.2.1. 대분류명을 수정할 경우, 해당 대분류에 소속되어 있는 하위 소분류 레코드들의 대분류명(`LargeClassificationName`) 컬럼도 동시에 일괄 업데이트 처리하여 데이터의 불일치 현상을 방지합니다.
- 3.2.2. 소분류명 수정 시에는 해당 소분류의 `SmallClassificationName`만 독립적으로 업데이트를 가하며, 공통 이력 필드(`UpdatingPerson`, `UpdatingDate`)를 갱신합니다.

### 3.3. 삭제 (Delete - 소프트 삭제)
- 3.3.1. **소분류 삭제:** 특정 소분류를 선택하여 삭제할 때, 해당 레코드의 `RecodingState` 값을 `0`으로 전환하여 조회 화면에서 비활성화 처리합니다.
- 3.3.2. **대분류 삭제 (연쇄 처리):** 대분류 자체를 삭제하는 경우, 해당 대분류 마스터 레코드뿐만 아니라 **이에 소속된 하위 모든 소분류 레코드들의 `RecodingState` 값 또한 `0`으로 연쇄적(Cascade)으로 일괄 업데이트**하여 소프트 삭제를 수행합니다.

> [!important] 비즈니스 제약 사항 (Validation)
> - 동일한 대분류 내에 중복된 소분류코드(`SmallClassificationCode`)가 존재해서는 안 됩니다.
> - `RecodingState`가 `0`인 데이터는 프론트엔드 코드 선택용 API 호출 시 반환 목록에서 필히 제외해야 합니다.
