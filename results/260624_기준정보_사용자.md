## 1. 개요
사용자정보(User Info)는 ERP 시스템에 로그인하여 업무를 수행하는 사원들의 마스터 데이터 및 시스템 접근 통제를 위한 기준 마스터 정보입니다. 기존 레거시의 불필요하고 정합성이 떨어지는 10여 개 필드(주민등록번호, 주소, 입사일, 직책 등)를 과감하게 다이어트하여 시스템 운영과 필수 업무 연동에 필요한 7대 핵심 필드 위주로 스키마를 최적화합니다.

## 2. 데이터베이스 설계안 (UI_MT)
사용자 정보 테이블은 일관된 정수형 기본키(`Index`) 매핑 및 유니크 제약 조건을 적용하여 아이디 중복을 물리적으로 예방합니다.

### 2.1. 사용자 정보 테이블 (UI_MT)
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `UserID` | `VARCHAR(100)` | NOT NULL | 로그인 아이디 (내용키, 식별자 코드, 고유값) |
| `Password` | `VARCHAR(255)` | NOT NULL | 비밀번호 (보안 적용을 위해 해싱 암호화 저장) |
| `UserName` | `VARCHAR(100)` | NOT NULL | 사원명 (실명) |
| `Contact` | `VARCHAR(100)` | NULL | 연락처 (휴대폰 번호 등) |
| `WorkDiaryGroupIndex` | `INT` | NULL | 업무일지그룹 식별 인덱스 (FK, 공용코드 PUC_MT 참조) |
| `AuthorityIndex` | `INT` | NOT NULL | 사용권한 식별 인덱스 (FK, 공용코드 PUC_MT 참조) |
| `Email` | `VARCHAR(255)` | NULL | 이메일 주소 (e-mail) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (소프트 삭제용 플래그, 기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 등록자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 등록일시 |
| `UpdatingPerson` | `VARCHAR(255)` | NULL | 수정자 |
| `UpdatingDate` | `DATETIME` | NULL | 수정일시 |

> [!important] 식별자 고유성 및 외래키 인덱스
> - 활성 상태(`RecodingState = 1`)에서 동일한 로그인 ID가 중복 등록될 수 없도록 `UQ_UI_MT_UserID` 고유 제약 조건을 적용했습니다.
> - `WorkDiaryGroupIndex` 및 `AuthorityIndex` 외래키 컬럼에 인덱스(`INDEX`)를 설정하여 사원 조회 및 로그인 인증 시 연관 데이터 조인 속도를 대폭 개선했습니다.

## 3. 핵심 비즈니스 로직 및 제약 사항

### 3.1. 로그인 아이디내용키 유일성 검증
- 3.1.1. **아이디 중복 검증:** 사용자를 등록 또는 수정할 때, 이미 시스템 상에 존재하는 활성 아이디(`UserID`)와의 중복 여부를 백엔드와 프론트엔드 양단에서 실시간으로 검증하여 가입을 통제합니다.

### 3.2. 업무일지 그룹 연동과 결재 결합 방식
- 3.2.1. **용도:** 매일 아침 사원들이 작성한 일일 업무 보고서를 사장에게 보고 및 결재 올릴 때, 부서나 업무 성격에 따른 보고서 결재 양식을 매핑하기 위해 업무일지그룹(`WorkDiaryGroupIndex`)을 사용합니다.
- 3.2.2. **동작 방식:** 사용자가 로그인하여 '업무일지 작성' 메뉴를 실행할 때, 시스템은 로그인 사용자 마스터에 지정된 업무일지그룹에 정의된 보고서 템플릿(예: 생산팀 양식, 영업팀 양식 등)을 자동으로 화면에 바인딩하여 줍니다.

### 3.3. 사용권한과 메뉴 제어 메커니즘
- 3.3.1. **메뉴 접근 통제:** 사원에게 배정된 사용권한(`AuthorityIndex`)은 공용코드의 권한 등급(예: 시스템관리자, 일반사용자, 조회전용 등)을 지시합니다.
- 3.3.2. **동작 방식:** 사용자가 시스템에 접속하면 백엔드로부터 배정된 사용권한 정보를 JWT 토큰에 담아 내려받으며, 프론트엔드는 이 등급을 기반으로 좌측 사이드바 메뉴(기준정보, 영업관리, 생산관리 등)의 노출 여부 및 편집 권한(읽기/쓰기)을 동적으로 제어합니다.

## 4. 화면 (UI/UX) 구성안 (다이어트 2분할 레이아웃)
기존의 불필요하고 번거로운 개인 정보 입력 필드들을 모두 정리하고 7대 정보 입력 위주로 슬림하게 구성합니다.

### 4.1. 좌측 영역 (사원 목록 그리드)
- 4.1.1. 부서별/권한별 사원 필터링 및 이름/ID 통합 검색 기능을 제공합니다.
- 4.1.2. 그리드 컬럼은 `아이디`, `이름`, `연락처`, `사용권한`, `업무일지그룹`으로 심플하게 구성합니다.

### 4.2. 우측 영역 (상세 정보 및 권한 편집 폼)
- 4.2.1. 필수 입력 필드(`아이디`, `비밀번호`, `이름`, `사용권한`)는 붉은색 별표 표시로 강조하여 입력을 누락하지 않도록 돕습니다.
- 4.2.2. **공용코드 연동 콤보박스:** `사용권한` 및 `업무일지그룹` 필드는 공용코드 마스터로부터 정형 데이터를 조회하여 안전한 드롭다운 UI로 제공합니다.
- 4.2.3. 이메일 주소 입력란에는 정규식 검증 규칙을 적용하여 `@` 및 도메인 포맷 누락 시 경고 문구를 동적으로 출력합니다.
