## 1. 개요
공정순서정보(Routing)는 생산 가공이 필요한 제품 및 반제품(모품목)이 완성되기까지 거쳐야 하는 작업 단계와 그 순서(Sequence)를 정의하는 기준 마스터 정보입니다. 기존 레거시의 가짜 더미 공정코드(14000000, 14009999)를 완전히 몰아내고 정규화된 쿼리 결합 방식을 사용하며, 외래키는 대원칙에 따라 정수형 기본키(`Index`) 매핑으로 통일합니다.

## 2. 데이터베이스 설계안 (PSI_MT)
공정순서 테이블은 품목과 공용코드의 공정 소분류를 1:N 관계로 맵핑하며, 자가/외주 구분 및 매핑 작업장 정보를 함께 관리합니다.
| 컬럼명 | 데이터 타입 | Null 여부 | 속성 및 용도 |
|---|---|---|---|
| `Index` | `INT` | NOT NULL | 고유 식별 일련번호 (PK, AUTO_INCREMENT) |
| `ItemIndex` | `INT` | NOT NULL | 대상 품목 인덱스 식별자 (FK, II_MT 참조) |
| `ProcessIndex` | `INT` | NOT NULL | 적용 공정 인덱스 식별자 (FK, 공용코드 PUC_MT 참조) |
| `ProcessSequence` | `INT` | NOT NULL | 공정 진행 순서 (예: 10, 20, 30...) |
| `WorkDivision` | `VARCHAR(100)` | NOT NULL | 작업 구분 ('자가', '외주', '자가/외주') |
| `WCIndex` | `INT` | NULL | 작업장 식별 인덱스 (FK, WCI_MT 참조, 자가 및 자가/외주일 때 필수) |
| `OutsourceLeadTime` | `INT` | NULL | 외주 리드타임 (일 단위, 외주 및 자가/외주일 때 필수) |
| `OutsourceRate` | `DECIMAL(5,2)` | NULL | 외주 발주 비율 (%, 자가/외주일 때 필수, 기본값 0.00) |
| `RecodingState` | `TINYINT(1)` | NOT NULL | 레코드 제어 상태 (소프트 삭제용 플래그, 기본값 1) |
| `RegistrationPerson` | `VARCHAR(255)` | NOT NULL | 등록자 |
| `RegistrationDate` | `DATETIME` | NOT NULL | 등록일시 |
| `UpdatingPerson` | `VARCHAR(255)` | NULL | 수정자 |
| `UpdatingDate` | `DATETIME` | NULL | 수정일시 |

## 3. 비즈니스 로직 및 제약 사항
### 3.1. 내용키 고유성 및 유효성 검증
- 3.1.1. **내용키 중복 검증:** 활성 데이터(`RecodingState = 1`) 내에서 동일 품목(`ItemIndex`)에 동일한 공정(`ProcessIndex`)이 두 번 등록될 수 없도록 고유 제약 조건을 검증합니다.
- 3.1.2. **순서 번호 부여 규칙:** 공정의 우선순위를 직관적으로 표시하기 위해 순서 번호(`ProcessSequence`)는 10단위(10, 20, 30...)로 건너뛰어 부여합니다. 이는 현업에서 중간에 신규 공정이 긴급 삽입되는 경우(예: 10과 20 사이에 15공정 삽입) 유연하게 대처하기 위함입니다.

### 3.2. 레거시 더미 데이터 배제 및 조회 최적화
- 3.2.1. **원자재 공정 배제:** 공정이 존재하지 않는 원자재나 외주 매입 상품은 공정순서 테이블(`PSI_MT`)에 **데이터 자체를 생성하지 않습니다.**
- 3.2.2. **외부 조인 (LEFT OUTER JOIN) 강제:** 공정이 없는 품목 조회 시 데이터가 누락되는 현상을 막기 위해, 백엔드 API 서비스 쿼리 구현 시 반드시 `LEFT OUTER JOIN`으로 품목 테이블과 공정순서 테이블을 결합하여 데이터를 서빙합니다.

### 3.3. 공정품(WIP) 재고 수량과의 관계
- 3.3.1. **재공 재고 매핑:** 특정 공정이 끝난 실물 상태는 '공정품'으로 취급됩니다. 예를 들어 'A품목-도금공정'의 실적 등록이 완료되면, 재고 테이블(`Inventory_T`)에 해당 품목의 `ItemIndex`와 생산공정 창고의 `WarehouseIndex`에 기반하여 도금 완료 수량이 적재 및 관리됩니다.

### 3.4. 자가/외주 비율에 따른 작업계획 분할 모델 (중요)
- 3.4.1. **분할 규칙:** 특정 공정의 작업구분이 '자가/외주'로 지정된 경우, 향후 작업계획 수립 단계에서 해당 공정은 1개의 지시가 아닌 **'자가 지시'와 '외주 지시'의 2개 레코드로 분할 생성**됩니다.
- 3.4.2. **수량 분할 계산 예시:**
  - 조건: A품목 밴딩 공정이 '자가/외주' 이며, 외주발주비율이 **40%**로 등록되어 있는 경우.
  - 시나리오: 생산 계획부서에서 A품목의 총 작업지시 수량을 **200개**로 확정하여 배정하는 상황.
  - 결과: 시스템은 내부적으로 2개의 계획 레코드를 자동 분할 수립합니다.
    - `A품목-밴딩(자가)` : 작업지시 수량 **120개** (200개 * 60%)
    - `A품목-밴딩(외주)` : 작업지시 수량 **80개** (200개 * 40%)

## 4. 화면 (UI/UX) 구성안 (표준 2분할 레이아웃)
일반 기준정보 화면 레이아웃과 일관성을 유지하되, 공정의 순차적 흐름을 시각적으로 확인할 수 있는 컴포넌트를 조화시킵니다.

### 4.1. 좌측 영역 (품목 리스트)
- 4.1.1. 상단에 품목명/품목번호 검색창과 자산분류 필터를 배치합니다.
- 4.1.2. 그리드에는 공정 정의가 필요한 대상 품목 목록(제품, 반제품)을 조회하고 선택할 수 있게 합니다.

### 4.2. 우측 영역 (공정순서 상세 및 편집 폼)
- 4.2.1. **공정 순서 그리드:** 선택한 품목의 등록된 공정들이 순서(`ProcessSequence`)에 맞춰 내림차순 정렬되어 표출됩니다. 그리드 컬럼에 '작업구분', '작업장명', '발주비율', '리드타임'이 추가 표시됩니다.
- 4.2.2. **상세 편집 폼:** 상단에 공용 공통 제어 버튼(초기화, 저장, 삭제)을 배치합니다.
- 4.2.3. **동적 입력 필드 제어 (UX):** 사용자가 '작업구분' 드롭다운을 선택함에 따라 입력 필드를 동적으로 활성화/비활성화 제어합니다.
  - **'자가' 선택 시:** 작업장(`WCIndex`) 입력칸 활성화(필수), 외주리드타임 및 외주비율 입력칸 비활성화(정리).
  - **'외주' 선택 시:** 외주리드타임 입력칸 활성화(필수), 작업장 및 외주비율 입력칸 비활성화.
  - **'자가/외주' 선택 시:** 작업장, 외주리드타임, 외주발주비율(%) 입력칸 **모두 활성화(필수)**.
